## 一句话总结

> **当前所有 agent 框架都是"小时级"设计的。要让 agent 7×24 连续工作，瓶颈不在模型能力，在基础设施。**

---

## 1. 问题：Agent 能跑多久？

我们拆了两个生产级 agent 框架的源码：

| 框架 | 语言 | 代码量 | 特点 |
|---|---|---|---|
| **kimi-code**（Moonshot） | TypeScript | ~10 万行 | DI 架构 + wire.jsonl 事件溯源 |
| **Grok Build**（SpaceXAI） | Rust | ~134 万行 | Actor 架构 + SQLite + 70+ crate |

发现一个关键事实：**它们都只设计到"小时级"**。

什么是"小时级"？一个 session 从用户发第一条消息开始，agent 跑几十轮，compaction（上下文压缩）两三次，完成一两个 goal，session 结束。

但 AGI 的目标是 **7×24 连续运行** —— 跑几天、几周、几个月不崩溃。

这不是量变，是**质变**：

| 维度 | 当前（小时级） | 7×24（天到月） |
|---|---|---|
| 轮次 | ~100 | ~10,000+ |
| 压缩次数 | 2-3 次 | ~200-500 次 |
| 完成的目标数 | 1-5 个 | ~100-1,000 个 |
| Token 消耗 | ~几十万 | **~数亿** |
| 状态日志大小 | ~MB | **~GB 到 TB** |

## 2. 五种"死法"：当前框架在 7×24 下会怎么崩

### 死法 1：压缩的"传话游戏"

当前 agent 用 compaction 压缩旧消息：旧对话 → LLM 生成摘要 → 用摘要替换旧消息。

7×24 下要压缩 **200-500 次**。第 200 次的摘要是什么？

```
摘要(摘要(摘要(摘要(... 摘要(原始对话) ...))))
```

就像传话游戏 —— 传 200 遍后，最初的信息**完全失真**。

我们把这个叫"语义漂移"（semantic drift）。这是**假设**（hypothesized），还没大规模实测验证 —— 但从信息论角度看，有损压缩链的累积失真是无法避免的。

### 死法 2：成本爆炸

每次"反熵"操作都要花钱：

| 操作 | 单次成本 | 月成本 |
|---|---|---|
| 上下文压缩 | $0.01-0.05 | $6-300 |
| 目标验证（skeptic panel） | $0.05-0.20 | $15-600 |
| 续跑提示注入 | $0.001 | ~$70 |
| 目标规划 | $0.02-0.05 | $3-75 |
| **合计** | | **$94-1,045/月** |

这只是"维护"的成本，不算 agent 正常工作的 token。

如果用下一代更强的模型（可能贵 5-10 倍）：**每月 $500-10,000**。

### 死法 3：状态日志无限增长

| 时间 | wire.jsonl / SQLite 大小 |
|---|---|
| 1 天 | ~10-50 MB |
| 1 个月 | ~300 MB - 1.5 GB |
| 1 年 | ~3.6 - 18 GB |

恢复时从头重放？GB 级日志要重放几小时。当前框架没有**自动的日志压缩**（把旧操作合并成快照）。

### 死法 4：身份漂移

经过 500 次压缩后，agent 的 context 和第一天**完全不同**。

我们定义了"身份持久化"：**一条不被压缩的因果链**，包含：
- (a) 原始目标声明
- (b) 所有关键决策及其理由
- (c) 所有安全约束的调用和变更

没有这条链，agent 就像失忆的人 —— 它可能还在"工作"，但已经不记得自己为什么要做这些了。

### 死法 5：慢速 Doom Loop

Grok Build 有 doom loop 检测器，但它只看**单次推理流**（秒级）。

7×24 下有一种**慢速 doom loop**：
- 连续 3 天反复"修同一个 bug"（每次压缩后忘了之前试过什么）
- 每个 goal 都"差一点"完成
- 在 100 个任务间反复横跳

这种天级循环，当前的检测器完全捕捉不到。

## 3. 和已有工作的区别

有人会问：Generative Agents（Stanford 小镇）和 Reflexion 不已经做了多日运行和自我反思吗？

**是的，但有关键区别**：

| 维度 | Generative Agents / Reflexion | 我们的提案 |
|---|---|---|
| **环境** | 模拟环境 | **生产环境** |
| **工具执行** | 无真实工具 | **真实 shell / 文件 / API** |
| **成本约束** | 无 | **有（Table 2）** |
| **安全验证** | 无 | **有（skeptic panel + sandbox）** |
| **记忆层级** | 1-2 层 | **5 层（含不可压缩的身份层）** |
| **自演化** | 任务级反思 | **系统级 prompt 演化** |

**核心区别**：它们是研究原型，我们讨论的是生产基础设施。

## 4. 需要的五种新能力

### ① 多尺度记忆层级

借鉴人脑的记忆分层（Atkinson & Shiffrin 1968），设计 5 层记忆：

| 层 | 时间尺度 | 容量 | 巩固方式 |
|---|---|---|---|
| 工作记忆 | 秒 | ~200K token | 每轮压缩 |
| 情景记忆 | 分钟-小时 | ~5K token | 每小时结构化提取 |
| 日记忆 | 小时-天 | ~2K token | 每天总结 |
| 周记忆 | 天-周 | ~1K token | 每周回顾 |
| 身份层 | 永久 | ~200 token | **永不压缩** |

每层做**结构化提取**（决策/结果/教训），不是无脑摘要。

### ② 离线巩固（"睡眠"）

人类睡眠时大脑会**回放**白天的经历，把重要的固化到长期存储。Agent 也需要：

- **活跃期**（~16h）：正常工作
- **巩固期**（~4h）：离线回放 + 提取教训 + 丢弃冗余
- **深度维护**（~4h）：日志压缩 + 知识图谱更新 + prompt 优化

**需要 agent 暂停工作** —— 这是和"永远在线"设计的根本区别。

### ③ 自演化 Prompt

当前 system prompt 是人写的、静态的。7×24 的 agent 应该能**自己改进自己**：

```
经验：用户 10 次拒绝 rm -rf 命令
→ 自动在 prompt 里加"避免破坏性命令"
```

**安全约束**：自演化不能降低安全级别。需要一层**不可变的宪法 prompt**。

### ④ 自适应验证

不是每个 goal 都需要全 skeptic panel。按风险分级：

| 风险 | 验证方式 | 例子 |
|---|---|---|
| 低 | 自动（diff 非空检查） | 改 typo |
| 中 | 1 个 skeptic | 重构函数 |
| 高 | 3-5 个 skeptic | 新功能 |
| 关键 | 全 panel + 人工审批 | 部署生产 |

### ⑤ 成本意识

Agent 需要知道"自己花了多少钱"：
- 每日/每周/每月预算
- 用小模型做 skeptic（不需要全能力）
- 用算法替代部分压缩（提取式摘要，不需要 LLM）
- 缓存重复验证

## 5. 路线图

### 短期（现有框架可以加）
1. 日志自动压缩
2. 结构化压缩（替代自由文本摘要）
3. 日/周预算管理
4. 验证结果缓存

### 中期（需要新模块）
5. 多尺度记忆（5 层）
6. 巩固模式（"睡眠"）
7. 知识图谱提取
8. 自适应验证（风险分级）

### 长期（根本性变革）
9. 自演化 prompt（带安全约束）
10. 身份持久化（不可压缩的因果链）
11. 慢速 doom loop 检测（跨 session 行为分析）
12. 反熵成本降低 10 倍

---

## 6. 局限性（诚实声明）

- **样本量**：只拆了 2 个框架。Claude Code / Cursor 可能不同。
- **成本估算**：基于假设的工作负载和 2025-2026 价格，是**示意性的**，不是实测。
- **压缩退化**：是**假设**，不是实测。验证它是未来的重要工作。
- **慢速 doom loop**：是**预测**，不是观测到的。

---

## 7. 核心结论

> **AGI 的最后一公里，不是模型能力，是基础设施。**

当前最好的 agent 框架都是"小时级"的。要让 agent 跑 7×24 不崩溃，需要全新的记忆架构、睡眠机制、自演化能力。

**谁先解决了 7×24 的基础设施问题，谁就真正实现了 AGI。**
