## 🔥 必须深挖(2 条)

### 🔥-1 · Cognition《Don't Build Multi-Agents》—— 单 agent + 持续 context 反多 agent

- **来源**:cognition.com/blog/dont-build-multi-agents(Walden Yan,Cognition CPO)+ latent.space 访谈《The Age of Async Agents》
- **主题**:① Agent 框架 ③ 7×24 长时运行
- **类型**:工程博客(官方)+ 访谈
- **核心主张**:Cognition(Devin,$26B 估值)押注 **single-threaded continuous context agent**,反对多 agent 分工。理由:子 agent 之间 context 不共享,会导致工作不一致;多 agent 切片 shared memory 会引入 divergence。Walden Yan 原话:"用户应该感觉在和一个连续的决策者、一个连续的意识对话"。
- **对项目的含义**:**挑战 insights 系列的多 agent 倾向**。具体:
  - 挑战 [01-multi-agent-scheduling.md](../../insights/01-multi-agent-scheduling.md) 整篇的前提(多 agent 调度是有价值的)
  - 挑战 [10](../../insights/10-memory-frameworks.md) §1 Letta 的"agent 自管理记忆"—— Letta 让 agent 自己管 memory,但 Cognition 说"让一个连续意识管所有事"
  - 挑战 [07](../../insights/07-philosophy-deep-dive.md) §2 关于"真正协作需要心智理论"—— Cognition 的立场是"协作 = 一个意识",不是"多个意识共享 context"
  - 但**印证 [13](../../insights/13-reconstructive-memory.md) §1.2**:Walden 用"continuous consciousness"这个词,正是 Parfit 因果连续性([07](../../insights/07-philosophy-deep-dive.md) §4)的工程化表述
- **是否值得深挖**:**🔥 必须写进未来 insights**。这可能是下一篇(insights/15)的主题 —— "单 agent vs 多 agent:Cognition 的反命题"。需要仔细读 Cognition 博客原文 + Anthropic 的反方立场(Anthropic 倾向 multi-agent),把这场架构路线之争写清楚。

### 🔥-2 · 智谱 GLM-5.2 · 1M 无损上下文,专为 Coding Agent 长时作业训练

- **来源**:z.ai/blog/glm-5.2 + 智谱 AI 开放文档 + 知乎深度解析
- **主题**:⑥ 长上下文 ⑧ Scaling laws
- **类型**:开源模型发布
- **核心数据**:
  - 1M token 无损上下文窗口
  - 实测单次任务累计处理 **85 万 token**(接近用满 1M)
  - 专门针对 Coding Agent 长时作业做了数月强化训练
  - 性能介于 Claude Opus 4.7 与 ...(被截断)之间,在多个长程任务基准上
- **对项目的含义**:**直接挑战 [09](../../insights/09-stateless-function.md) §4 的"长上下文撞三堵墙"**。具体:
  - 挑战墙一(O(n²) 注意力):GLM-5.2 的 MoE 架构 + 数月长程训练,实证 85 万 token 稳定可用,说明注意力墙**正在被工程化绕过**
  - 挑战墙二(lost in the middle):智谱宣称"无损" —— 需要验证,但如果是真的,说明 [09](../../insights/09-stateless-function.md) §4 墙二也在被攻破
  - **但**:这恰好**印证 [09](../../insights/09-stateless-function.md) §4 开头说的"长上下文是检索问题的逃生舱"** —— 智谱走的是模型侧路线,把检索需求消解在模型容量里
  - 印证 [05](../../insights/05-agi-7x24.md) §4 的判断("模型侧反熵派")—— 智谱是这一派的最新代表
- **是否值得深挖**:**🔥 必须验证**。"1M 无损"是强声明,需要查智谱的 benchmark 细节 —— 是真的全 1M 无损,还是"前 200K + 后续衰减"。如果真的全 1M 无损,[09](../../insights/09-stateless-function.md) §4 的三堵墙需要重新评估。

### ⭐-3 · Anthropic《Effective context engineering for AI agents》

- **来源**:anthropic.com/engineering/effective-context-engineering-for-ai-agents
- **主题**:② Agent 框架(Claude Code)⑥ 长上下文
- **类型**:Anthropic 官方工程博客
- **核心**:Anthropic 提出"context engineering"取代"prompt engineering"。Claude Code 用 CLAUDE.md 前置注入 + glob/grep 即时检索的混合模型,bypass 传统索引问题。长任务通过让模型自己总结压缩历史。
- **对项目的含义**:**多处印证**:
  - 印证 [09](../../insights/09-stateless-function.md) §3"所有记忆都是检索+注入"—— Anthropic 自己把这件事命名为 "context engineering"
  - 印证 [13](../../insights/13-reconstructive-memory.md) §1.2 "系统提示词作为身份层"—— CLAUDE.md 就是前置注入的"项目身份层"
  - **挑战 [10](../../insights/10-memory-frameworks.md) §1 的 Mem0 MCP 路径** —— Anthropic 不用专门记忆服务,用 CLAUDE.md + 文件系统原语(grep/glob)就够了。这是第六种架构:**无记忆服务,靠文件系统 + 注入**
- **是否值得深挖**:⭐ 值得单独拆 Claude Code 的 context engineering 实现。

### ⭐-4 · CausalBench / CLadder / CounterBench / CausalDS —— 因果推理 benchmark 一批

- **主题**:⑤ 因果推理
- **类型**:多个 benchmark
- **核心**:一批用 Pearl Ladder 评 LLM 因果推理的 benchmark。Nature 2026 医学论文显示 GPT-o1 在 counterfactual rung 上达到 0.92(对 Llama 3.2 的 0.62)。
- **对项目的含义**:**挑战 [11](../../insights/11-causal-state-store.md) §4 的"agent 因果只能到第 1 层"**。我 11 §4 说"第 3 层反事实对 agent 基本不可能",但 Nature 论文显示 GPT-o1 在医学场景的反事实推理达到 0.92 —— 这说明**强模型 + 好场景设计,反事实推理是可行的**。11 §4 的边界需要放宽。
- **是否值得深挖**:⭐ 值得重写 11 §4 的边界判断。
