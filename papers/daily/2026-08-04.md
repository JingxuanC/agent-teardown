## 🔥 必须深挖(4 条)

### 🔥-1 · LoCoMo Benchmark 答案 6.4% 错误——所有记忆排名需要重审

- **来源**：arXiv:2607.21962 · "Ground Truth First: A Longitudinal Evaluation Instrument for Agent Memory"
- **主题**：⑤ benchmark
- **核心**：Penfield Labs 独立审计发现 LoCoMo benchmark 的 1,540 个答案中有 **99 个（6.4%）是错的**。这些不是边缘案例——涉及 temporal reasoning、causal reasoning 和 event ordering 类型的核心问题。论文指出"conversation-first" benchmark 设计（先生成对话，再提取答案 key）系统性地产生标签错误和污染。当使用"ground-truth-first"（先确定真实事件，再生成对话）重新评估时，之前接近饱和的系统排名剧烈变化。
- **对项目的含义**：
  - **causal-memory 的 LoCoMo 67.4% 需要重新解读** —— 6.4% 的答案错误意味着天花板不是 100%，而是 ~93.6%。我们的 67.4% 可能比看起来更接近某些竞品
  - **应该考虑用 LongMemEval 作为主 benchmark** —— 它经过更严格的审计，问题质量更高
  - **BEAM benchmark** 是新出现的"百万 token 级"长程记忆 benchmark，值得评估
- **是否值得深挖**：🔥 **必须**

### 🔥-2 · Oracle Agent Memory：LongMemEval 93.8% 新 SOTA

- **来源**：arXiv:2607.13157 · Oracle (Alake, 2026)
- **主题**：① Agent 记忆 ⑤ benchmark
- **核心**：Oracle 发布了一个企业级记忆系统，在 LongMemEval 上达到 **93.8%（469/500）** 的准确率——大幅超过 Mem0（~64%）、A-MEM（~50%）等。关键设计：
  1. **生命周期管理**：ingestion → extraction → consolidation → retrieval → summarization → revision/removal
  2. **分层 scope**：user / agent / thread / tenant 四级隔离
  3. **记忆修正**：当新证据推翻旧记忆时，支持 reversible consolidation
  4. **token 效率**：比 flat-history 少用 10.7x tokens
  5. **BEAM benchmark**：在百万 token 级长程记忆上达到 0.680
- **对项目的含义**：
  - **Oracle 的 lifecycle 设计和我们的 SWR consolidation + WriteBack 高度对应**——但 Oracle 做得更系统化
  - **reversible consolidation** 是我们缺少的——我们目前 consolidate 后不保留原图
  - **93.8% vs 我们的 67.4%**——差距 26pp，但 Oracle 用的是 LongMemEval（500 题），我们用的是 LoCoMo（1540 题，其中 6.4% 有错误）
- **是否值得深挖**：🔥 **必须**

### 🔥-3 · LazyMem：213 Token 达到 0.85 准确率（68.7x Token 节省）

- **来源**：arXiv:2607.22690 · "LazyMem: Retrieve Broadly, Construct Selectively"
- **主题**：① Agent 记忆 ④ 重构式 vs 检索式
- **核心**：LazyMem 提出了一个反直觉的策略——**不在写入时构建记忆，而是在查询时才构建**（defer all memory construction to query time）。具体做法：
  1. 写入时：只存储原始对话（不做任何提取/摘要）
  2. 查询时：广泛检索相关原始片段 → 选择性地构建极短的上下文（213 tokens）
  3. 结果：LongMemEval **0.85 LLM-judge 准确率**，用 **68.7x 更少的 token** 超过了 retrieval-only baseline
- **对项目的含义**：
  - **这是对 rate-distortion "可逆性 > 评分技巧"理论的完美验证** —— LazyMem 完全不做写入时压缩，只保留原始数据，查询时才构建。极端可逆
  - **和 RecMem（recurrence-based consolidation）形成对比** —— RecMem 在写入时 consolidate，LazyMem 在查询时 construct。两者代表记忆管理的两个极端
  - **causal-memory 可以学这个思路** —— session_logs（原始数据，不做压缩）+ 查询时的 causal extraction。我们目前的 distill 是写入时做的（eager），LazyMem 证明 lazy 可能更好
- **是否值得深挖**：🔥 **必须**

### 🔥-4 · AttriMem：RL 驱动的细粒度记忆管理（token 级 reward）

- **来源**：arXiv:2607.21106 · "AttriMem: Attribution-Guided Process Feedback for Agent Memory Learning"
- **主题**：① Agent 记忆 ⑦ 持续学习
- **核心**：AttriMem 用 RL 训练一个小模型（Qwen3-4B）来管理记忆操作（ADD/UPDATE/DELETE/NOOP），但关键创新是 **token 级别的 reward**：
  - RLOut（输出级 reward）：整体答案对错
  - RLAct（动作级 reward）：记忆操作是否正确
  - **RLTok（token 级 reward）**：每个 token 的贡献度
  - 结果：RLTok 比 RLOut 在 LoCoMo 上高 4.17pp。训练只用了 LongMemEval，但零样本迁移到 LoCoMo（82.48）和 PerLTQA（84.49）
- **对项目的含义**：
  - 继 MemRL/MemQ/DeltaMem/CMI-Mem 之后，又一个 RL-based 记忆管理。AttriMem 的 token 级 reward 是最细粒度的
  - **causal-memory 的 Q-value 更新可以考虑 token 级反馈** —— 不是整体"这次分析对不对"，而是"哪句话的因果推断最关键"
- **是否值得深挖**：⭐ 可选

## ⭐ 值得关注(3 条)

### ⭐-1 · Metis：记忆基础模型（Memory Foundation Model）

- **来源**：arXiv:2607.26760 · "Metis: Memory Foundation Model"
- **核心**：把记忆管理直接训练进模型权重——不是外部存储 + 检索，而是模型的参数本身就是记忆。在 LoCoMo 和 NextMem 上取得大幅提升
- **对项目的含义**：参数化记忆方向（模型内部 vs 外部存储）值得关注，但和 causal-memory 的外部存储路线不同

### ⭐-2 · MemLens：价值感知记忆管理系统（可视化 + 审计）

- **来源**：arXiv:2607.25992 · "MemLens: A Value-Aware Memory Management System"
- **核心**：让用户可视化检查 agent 的记忆——查看记忆值、层级结构、比较不同记忆管理策略
- **对项目的含义**：causal-memory 需要类似的记忆审计/可视化工具

### ⭐-3 · Memory 提取攻击：持久化注入可跨 session 影响 agent

- **来源**：arXiv:2607.23444 · "Isolated but Exposed: Persistence-Based Memory Extraction Attack"
- **核心**：注入到 agent 记忆中的恶意内容可以跨 session 持续存在，影响后续所有推理。论文展示了记忆作为攻击面的风险
- **对项目的含义**：causal-memory 的 prevented 负扩散可能天然抵御这类攻击——恶意内容被标记为 prevented → 负权重 → 传播时被抑制
