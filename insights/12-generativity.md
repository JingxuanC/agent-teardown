# Insights · 生成性 —— Agent 的另一半

> 本篇是 [08-self-rebuttal.md](08-self-rebuttal.md) 反驳 4 的**正面展开**。
>
> [08](08-self-rebuttal.md) 反驳 4 说:"反熵(反退化)是一个维护性框架,不是创造性框架。它解释了'怎么不崩溃',但解释不了'怎么产生价值'。" [09](09-stateless-function.md) §7 把它列为唯一一个"被框定但未解决"的反驳。本篇填这个洞。
>
> 核心论点:**Agent = 反退化(维护) + 生成(创造)。前 11 篇 insights 只讲了前半句。本篇讲后半句 —— 生成性从哪来,它和反退化的边界在哪,7×24 AGI 需要什么样的生成性。**
>
> 诚实地预告结论:**生成性比反退化更难**。反退化有五种策略、42 篇代码、4 家公司做印证;生成性连"它是什么"都还在争论。本篇只能给出框架,不能给答案。

## 0. 起点:反退化框架的盲区

[04](04-anti-entropy.md)(信息论重构版)建立了一个完整的反退化框架:agent 对抗四种信息退化(信噪比下降、状态膨胀、召回失败、行为收敛),五种策略(压缩、隔离、验证、恢复、约束)覆盖所有退化源。

但 [08](08-self-rebuttal.md) 反驳 4 戳穿了一个盲区:

> 反退化框架能解释 compaction(压缩 = 减退化)、skeptic(验证 = 减少召回失败)、sandbox(隔离 = 防止退化扩散)。但它解释不了:
> - agent **为什么能写出正确的代码**?(这不是反退化,是**生成**)
> - agent **为什么能找到 bug**?(这不是反退化,是**推理**)
> - agent **为什么能回答用户的问题**?(这不是反退化,是**理解**)

**反退化是一个维护性框架,不是创造性框架。** 它解释了"怎么不崩溃",但解释不了"怎么产生价值"。如果一个 agent 的全部工作就是反退化(compaction + 验证 + 隔离 + 恢复 + 约束),它永远不会做任何有用的事 —— 它只是在"维持自己的存在",但没有"做任何事"。

## 1. Agent = 反退化 + 生成

一个完整的 agent 同时做两件事:

```
Agent = 反退化(维护秩序,对抗信息损失)
      + 生成(创造价值,产出有用的输出)
```

### 两件事的分工

| | 反退化 | 生成 |
|---|---|---|
| **做什么** | 维持 context 的信息质量 | 用 context 产出有用的输出 |
| **谁在做** | **框架**(compaction / skeptic / sandbox / ...) | **LLM 本身**(推理 / 生成) |
| **衡量标准** | 稳定性(不崩溃、不漂移) | 价值(代码正确、bug 被找到、问题被回答) |
| **失败模式** | doom loop / 漂移 / 崩溃 | 幻觉 / 错误答案 / 低质量输出 |
| **insights 覆盖** | 04-11(11 篇) | **本篇(第一次)** |

### 为什么前 11 篇只讲了前半句

不是偏科,是**拆解的必然结果**。42 篇代码拆解看的全是框架代码 —— compaction 的实现、skeptic 的调度、sandbox 的权限链、doom loop 的检测。这些全是反退化代码。**生成性不在框架代码里,在 LLM 的推理里。** 你拆不出"LLM 为什么能写对代码",因为那不在代码里,在模型的训练数据 + 权重里。

> **关键区分:框架产出反退化,LLM 产出生成性。框架的代码决定了 agent 的"维护质量",LLM 的能力决定了 agent 的"生成质量"。**

## 2. 生成性从哪来

[09](09-stateless-function.md) 已经给出了答案的物理基础:

```
LLM 是无状态的纯函数:output = f(context)
```

**生成性就在这个 `f` 里。** `f` 是 LLM 的训练数据 + 模型权重定义的函数。当你给它一个好的 context(反退化保证的),它调用 `f` 产出输出。这个 `f` 做的事 —— 推理、关联、生成代码、理解意图 —— **就是生成性**。

### `f` 和 `context` 的分工

| | `context`(反退化的领地) | `f`(生成的领地) |
|---|---|---|
| 谁控制 | 框架(检索 + 组装) | LLM(训练 + 推理) |
| 包含什么 | 用户请求、历史摘要、工具结果、系统提示 | 训练数据中习得的所有模式 |
| 改善方式 | 更好的检索、更好的压缩、因果图 | 更好的训练、更多数据、更强架构 |
| 失败时 | 召回失败 → 幻觉(信息不足) | 推理错误 → 错误答案(能力不足) |

### 这个分工的三个推论

**推论 1:生成性的天花板由 `f` 决定,不由框架决定。** 一个完美的反退化框架(从不丢信息、从不崩溃)配上一个糟糕的 LLM,产出的仍然全是垃圾。反退化保证 `f` 有好的输入,但不能让 `f` 变聪明。

**推论 2:反退化的价值依赖于 `f` 的能力。** 如果 `f` 足够强(GPT-5 / Claude 4),它能在**残缺的 context** 里推出正确答案 —— 弱化反退化的需求。如果 `f` 很弱,再好的反退化也救不了它。**模型越强,反退化的边际收益越低。**

**推论 3:两者相互依赖,不能完全替代。** `f` 再强,context 完全空了它也无能为力(幻觉);反退化再好,`f` 推理不出答案它也产出不了价值。一个好的 agent 需要**两者协同**:反退化给 `f` 足够好的 context,`f` 用这个 context 生成价值。

## 3. 反退化 vs 生成的失败分类

[06](06-open-questions.md) ① 问"agent 犯错时是哪个环节的锅"。现在可以给出比 06 原文(都是"熵")精确得多的分类:

| 失败类型 | 根因 | 归属 | 修复方向 |
|---|---|---|---|
| **召回缺失** | context 没包含关键信息 | 反退化(检索 / 压缩) | 更好的检索([11](11-causal-state-store.md)) |
| **信噪比差** | context 包含太多噪音 | 反退化(压缩 / 隔离) | 更好的压缩 / 分层 |
| **推理错误** | LLM 推理链断了(即使 context 完整) | **生成** | 更强的模型 / few-shot |
| **知识缺失** | LLM 训练数据里没有相关知识 | **生成** | RAG / fine-tune / 更新模型 |
| **对齐偏差** | LLM 理解的目标和用户真实目标不一致 | **生成** | 更好的 prompt / goal 建模 |

**前三类(召回缺失、信噪比差)是反退化问题,后三类(推理错误、知识缺失、对齐偏差)是生成问题。** 反退化措施(compaction / skeptic / sandbox)只能修复前三类;后三类需要换更强的模型、补 RAG、或改 prompt 工程。

### 这个分类的实操含义

当 agent 出错时,先沿 [11](11-causal-state-store.md) §5 的因果链回溯,判断是哪一类:
- 如果 context 里该有的信息没有 → **反退化问题** → 改检索 / 压缩策略
- 如果 context 完整但答案错了 → **生成问题** → 换模型 / 改 prompt / 补知识

**这个二分法把"调试 agent"从黑盒变成了可归因的诊断流程。**

## 4. 生成性能改善吗

这是 7×24 AGI 的核心问题。

反退化可以靠工程改善(更好的 compaction、更强的 skeptic、因果图)。**但生成性呢?** 一个 agent 跑 30 天后,它的 `f` 会变强吗?

### 三种可能

| 路径 | 怎么做 | 当前状态 |
|---|---|---|
| **换更强的模型** | GPT-5 → GPT-6 → ... | 每次需要重新训练,$数千万 |
| **Fine-tune** | 用 agent 的经验微调模型权重 | 灾难性遗忘 / 成本高 / 不安全 |
| **Token 空间持续学习** | 不改权重,改 context(learned context) | **Letta 的押注**(见 [10](10-memory-frameworks.md) §4) |

### Letta 的押注:权重是临时的,learned context 才是持久的

[10](10-memory-frameworks.md) §4 引用过 Letta 的 Continual Learning in Token Space 论文(2025-12):

> "Memories learned in token space become **more valuable than the model weights themselves**: agents run perpetually, gradually enriching learned context through trillions of tokens of experience data, **seamlessly transferring their memories across many generations of models**."

这是一个**非常强的赌注**。它在说:生成性能改善,但不是通过改 `f`(权重),而是通过改 context(learned context)。agent 的"成长"不在于它变聪明了(模型没变),在于**它积累了更好的 context** —— 把经验固化成 token,塞进 context 让 `f` 用。

### 但 token 空间持续学习有天花板

learned context 仍然要塞进有限的 context window。而且:

- 它**依赖 `f` 本身够强** —— 如果 `f` 不能从 learned context 里"读出"教训,积累再多也没用
- 它**不可靠** —— learned context 可能包含错误教训(就像人可能"学到错的")
- 它**没有能力跃迁** —— learned context 让 agent 在**熟悉的场景**下更好,但不能让 agent 做它**从没见过的事**

**结论:生成性能改善,但改善的是"经验利用率",不是"基础能力"。** agent 的基础能力天花板仍然由 `f`(模型权重)决定。learned context 让 agent 更接近它的天花板,但不能提高天花板本身。

## 5. 7×24 AGI 需要什么样的生成性

把 §2-§4 接起来,7×24 AGI 的生成性需求:

```
7×24 的生成性 = f(模型能力) × 反退化质量 × 经验积累
```

| 因子 | 当前状态 | 7×24 需要 |
|---|---|---|
| `f`(模型能力) | 单次推理接近人类专家(GPT-5 / Claude 4) | 已够用 |
| 反退化质量 | 小时级(当前框架) | **月级**(需要 [11](11-causal-state-store.md) 的因果库 + [09](09-stateless-function.md) 的检索架构) |
| 经验积累 | 几乎为零(无 learned context) | **持续学习**(Letta 的 token-space 方向) |

### 关键洞察:7×24 的生成性瓶颈不在 `f`

GPT-5 / Claude 4 的单次推理**已经够强**。7×24 的瓶颈在于:

1. **反退化撑不到月级** → agent 在第 N 天因为 context 损坏而生成垃圾(反退化问题,不是生成问题)
2. **经验不积累** → agent 第 30 天和第 1 天犯同样的错(learned context 问题)
3. **`f` 不成长** → agent 遇到从没见过的场景仍然束手无策(基础能力问题,但短期不可解)

**前两个是工程能解决的(04-11 在做第 1 个,Letta 在做第 2 个)。第三个是模型训练问题,短期靠工程绕不开。**

### 所以 7×24 AGI 的路线图

```
短期(2-3 年):
  反退化从小时级提升到天/周级(04-11 的方向)
  + learned context 的雏形(Letta 的 sleep-time / continual learning)
  → 天级 7×24,生成性接近当前模型水平

中期(3-5 年):
  反退化到月级(因果状态库 + 任务感知检索 + 元学习)
  + learned context 成熟(跨模型迁移的经验积累)
  → 月级 7×24,生成性超过任何单次 session

长期(5+ 年):
  f 本身持续进化(continual learning 进权重 / 新架构)
  + 反退化和生成性融合(因果推理 [11](11-causal-state-store.md) §4 的 Pearl 第 2-3 层)
  → 真正的 AGI(不只是"跑得久",还有"越跑越强")
```

## 6. 生成性为什么比反退化更难

回到开头的预告:**生成性比反退化更难**。具体难在哪:

| 维度 | 反退化 | 生成性 |
|---|---|---|
| **可观测性** | ✅ 可测量(context 长度、崩溃频率、retry 次数) | ❌ 难测量(什么叫"好的输出"?) |
| **可工程化** | ✅ 五种策略,42 篇代码,4 家公司 | ❌ 没有通用策略,依赖模型本身 |
| **可归因** | ✅ 四种退化源,因果链回溯([11](11-causal-state-store.md)) | ⚠️ §3 给了五类,但边界模糊 |
| **可改善** | ✅ 更好的 compaction / 检索 / 验证 | ❌ 要么换模型($),要么靠 learned context(不成熟) |
| **理论基础** | ✅ Shannon 信息论([04](04-anti-entropy.md) / [09](09-stateless-function.md)) | ❌ 没有"生成性理论"(连 LLM 为什么 work 都还在争论) |

### 最根本的难:没有"生成性理论"

反退化有 Shannon 信息论做基础(09 把它精确到了 context 组装过程)。**生成性没有对应的理论。** LLM 为什么能推理?为什么能写对代码?为什么能理解意图? —— 这些问题的答案,目前最好的回答是"训练数据 + 规模 + 涌现",但**涌现本身就是一个我们不理解的现象**([06](06-open-questions.md) ②)。

[07](07-philosophy-deep-dive.md) §1 引用了 Nature 2026 的"机器经验主义" —— 说 LLM 有"第三种认知"(不是人类的理解,也不是纯统计)。但这只给了生成性一个**哲学定位**,没有给**工程抓手**。

**这就是为什么前 11 篇全在讲反退化** —— 不是因为生成性不重要,是因为反退化**有理论、可工程化、可测量**。生成性目前**没有理论、不可工程化、难测量**。本篇能做的只是把边界划清楚,给未来留一个"这里需要理论"的标记。

## 8. 最终的一句话

> **反退化是 agent 的免疫系统,生成性是 agent 的大脑。** 前 11 篇 insights 完整地拆解了免疫系统(五种策略、四种退化源、因果状态库、记忆公司赛道)。本篇第一次面对大脑 —— 然后发现我们对它的理解远不如对免疫系统的理解。
>
> 生成性来自 `f`(LLM 推理),不在框架代码里,在模型权重里。框架产出反退化,LLM 产出生成性。反退化的天花板是工程能力(可改善),生成性的天花板是模型能力(短期不可改善,只能靠 learned context 间接提升)。
>
> 7×24 AGI 需要两者协同:反退化撑到月级(04-11 的方向),生成性靠 learned context 积累经验(Letta 的方向)。**反退化的最后一公里是检索架构([09](09-stateless-function.md)),生成性的最后一公里是持续学习(Letta Continual Learning)。两条路都还在早期。**
>
> 最诚实的结论:**反退化有理论(Shannon),生成性没有理论。** 这是 agent 研究最大的理论空白,也是这篇只能给框架不能给答案的原因。
