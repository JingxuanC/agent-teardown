# Insights · 重构式记忆 —— 从检索到生成的范式转换

> 本篇由两次对话催生,值得记录这两次对话的源点。
>
> **第一轮**:用户提出"每次都发系统提示词,如果提供 tools 让 agent 自己去找因果链、找完整记忆呢" —— 这戳到了 [11](11-causal-state-store.md) §5 一个未分离出来的第三选项。
>
> **第二轮**:用户问"人回忆是不是也可以理解成 agent 找记忆"。直觉上像,但深入后反直觉:人脑回忆不是"找",是"重构"。这个区分暴露出**当前所有 agent 记忆都是检索式,没有一个做重构式**。
>
> 本篇把这两轮合并:第一轮的"agent 自检索 + 系统提示词"是**检索式**的极致形态(它解决了任务感知,但仍然是存原文召回原文);本篇进一步提出**重构式**才是更接近人脑、也更可能是 7×24 终局的范式。两轮合在一起,覆盖了 agent 记忆的第三和第四种架构哲学(前两种是 [10](10-memory-frameworks.md) 的外部检索 + Letta 自管理)。

## 0. 起点:两轮对话逼出的四个架构选项

[09-12](09-stateless-function.md) 建立了一个隐含假设:**agent 记忆 = 外部状态库 + 检索器**。[10](10-memory-frameworks.md) 把它落地到 Mem0/Zep/Letta/OpenViking/MemOS 五种实现。[11](11-causal-state-store.md) 进一步提出因果状态库。这两轮对话把这个假设炸开了 —— 原来至少有**四种**架构选项,不只是"用什么检索器":

| # | 架构 | 谁理解任务 | 记忆机制 | 代表 |
|---|---|---|---|---|
| 1 | **外部检索器** | 外部小模型 | 检索(存原文召回) | Mem0 / Zep / 09-11 隐含设计 |
| 2 | **Agent 自管理** | agent 自己 | 检索 + 自写记忆 | Letta |
| 3 | **Agent 自检索 + 系统提示词目录** | agent 自己 | 检索(目录常驻 + 详情按需) | **本篇 §1**(第一轮对话) |
| 4 | **重构式记忆** | agent 自己 | **重构**(存碎片,回忆时生成) | **本篇 §2-4**(第二轮对话)|

[11](11-causal-state-store.md) §5 默认了选项 1,但没把选项 3/4 作为独立方案呈现。这是 11 的一个未言明偏见 —— 本篇修正它。

# 第一部分:Agent 自检索 + 系统提示词目录(选项 3)

> 本部分对应第一轮对话:用户问"如果提供 tools 让大模型自己去找因果链、找完整记忆呢"。

## 1.1 这个方案为什么重要

[09](09-stateless-function.md) §5 和 [11](11-causal-state-store.md) §5 都说"需要任务感知检索器",但都没说清**怎么让检索器懂当前任务** —— 让一个小模型理解 LLM 正在做什么,本身就是一个难题。

用户的方案绕开了这个难题:**别让外部懂,让 agent 自己当那个懂的人。**

```
传统外部检索器:
  框架建检索器 → 检索器"猜"当前任务 → 从库里召回
  
Agent 自检索:
  agent 就是任务本身 → 天然懂任务 → 调工具找
```

**决定性优点**:免费解决任务感知。Agent 不会召回无关偏好(Mem0 的盲召回问题,见 [10](10-memory-frameworks.md) §5),因为它就是当前任务的执行者。

## 1.2 系统提示词作为"不可压缩的索引"

但 agent 自检索有一个硬伤:**它只能找它意识到的因果链,找不到它意识不到的。** 如果某条因果链在 k=10 次 compaction 后被压掉了([papers/02](../papers/02-compaction-degradation.md) 真实数据),agent 不知道它曾经存在过 —— 不会主动去调 `find_causal_chain` 找一个它不知道存在的东西。

这是"**元遗忘**"问题 —— 不知道自己忘了什么。

**解决方案:系统提示词常驻一个"因果链目录"**。这是用户那一轮的原话"每次都会发一个系统级别的 prompt"的关键洞察:

```
系统提示词(恒定,不压):
  你过去做过的关键决策:
   - D001: 用 Redis 做缓存 → 导致了 缓存击穿(O001)
   - D002: 用 mutex 加锁 → 导致了 死锁(O002)
   - D003: 用 channel 通信 → 修复了 race condition(O003)
   ...
   ↑ 每行只是一个"指针",不是完整内容
```

Agent 永远知道自己**有哪些**过去(目录常驻),只是不知道**细节**(详情按需拉取)。和人一样 —— 你知道自己结过婚、换过工作,但不记得某天的具体对话,需要时再回忆细节。

**系统提示词 = [07](07-philosophy-deep-dive.md) §4 Parfit 身份层的具体物理位置。** 07 说"需要不被 compaction 压缩的身份层",但没说它该放在哪。这一轮给出了答案:**放系统提示词里** —— 它是唯一每轮恒定注入、不被压缩的 context 部分。

## 1.3 完整架构:OpenViking 的 L0 + 工具 + 因果库

把第一轮的方案落地:

```
┌─────────────────────────────────────────┐
│ 系统提示词(每轮恒定注入,不被压缩)       │
│  - 身份("你是一个 7×24 编码 agent")    │
│  - 因果链目录(L0,每条一行摘要)        │ ← OpenViking L0 思想
└─────────────────────────────────────────┘
                    ↓
┌─────────────────────────────────────────┐
│ Agent 推理(LLM,无状态)                │
│  看到目录里 D002 相关                    │
│  → 调 trace_decision("D002")            │ ← agent 自检索
└─────────────────────────────────────────┘
                    ↓
┌─────────────────────────────────────────┐
│ 因果状态库([11] 的 CausalEdge)         │
│  返回 D002 的完整碎片 + 原文锚点         │ ← 11 的数据结构
└─────────────────────────────────────────┘
```

这合成了三个东西:
- **OpenViking 的 L0 分层加载**([10](10-memory-frameworks.md) §1):目录常驻,详情按需
- **11 的因果状态库**:CausalEdge 作为存储格式
- **用户的系统提示词洞察**:L0 放在系统提示词里,绕开元遗忘

## 1.4 诚实的代价

这个方案不是免费的:

| 维度 | 问题 |
|---|---|
| **Token 成本** | 每次 `trace_decision` 是一次 LLM 调用,比向量检索贵 |
| **系统提示词膨胀** | 因果链多了目录塞不下 —— 需要分页/聚类,又回到外部检索问题 |
| **可靠性** | LLM-in-the-loop 不可靠([10](10-memory-frameworks.md) §5 对 Letta 的批评同样适用)—— 可能调错工具、调漏工具、误读结果 |

**所以选项 3 在"任务感知"上胜过选项 1,在"成本和可靠性"上劣于选项 1。** 这是一个真实的权衡,不是哪个对。7×24 的终局很可能是混合:系统提示词放 L0 目录(永久知道自己有什么)+ 外部因果库存 L2 详情(便宜召回)+ agent 用工具深挖(任务感知)。

# 第二部分:重构式记忆(选项 4)

> 本部分对应第二轮对话:用户问"人回忆是不是也可以理解成 agent 找记忆"。

## 2.1 反直觉的答案:像,但机制本质不同

直觉上,"agent 找记忆 ≈ 人回忆"是个好类比。但现代认知科学从 Bartlett(1932)到 Schacter(2012,被引 281 次)到 Nature 2023(*A generative model of memory construction and consolidation*)有截然不同的共识:

> **人脑回忆不是"找记忆",是"重新生成记忆"。**

关键证据链:

1. **回忆和想象共用神经基底**(Schacter 的 constructive episodic simulation hypothesis)—— 回忆过去和想象未来用同一套脑区。如果是"检索",这两件事不会共用电路。
2. **回忆会改写记忆**(reconsolidation,Nader et al. 2000)—— 每次回忆,记忆变得不稳定,然后重新固化,期间被当前 context 篡改。这是证人证词不可靠的原因 —— 每次回忆都在重新生成。
3. **海马体 replay 训练生成模型**(Nature 2023)—— 睡眠时海马体回放碎片,训练皮层的生成模型(VAE-like)来重构体验。**记忆的本质是生成模型,不是存储。**

### 一张机制对比表

| | 人类回忆 | 当前 agent 找记忆 |
|---|---|---|
| 机制 | **重构**(生成) | **检索**(召回) |
| 存的是什么 | 碎片 + 图式(schema) | 完整文本 / 向量 / 图边 |
| 出错方式 | 重构偏差(记错) | 召回失败(找不到) |
| 会改写原记忆吗 | ✅ 会(reconsolidation) | ❌ 不会(存储只读) |
| 任务相关性 | ✅ 同一事件不同情境下回忆出不同侧面 | ❌ 同一查询永远返回同一结果 |

**当前所有 agent 记忆都是检索式的 —— 存原文,召回原文。没有一个做重构式。** 这是第二轮对话逼出来的最大发现。

## 2.2 但有一个更深的共同点(机制层同构)

第一轮我担心这又掉进 [08](08-self-rebuttal.md) 反驳 3 的修辞陷阱(植物类比不是同构)。但仔细看,人脑和 LLM 有一个**机制层**的同构,不是类比:

- **人脑**:没有独立于神经活动的"记忆硬盘",回忆是激活 + 生成
- **LLM**:无状态([09](09-stateless-function.md) §1),没有跨调用的"记忆",每轮的"记忆"都是组装 context + 推理生成

**两者都是"生成式记忆",只是生成的位置不同 —— 人在海马体-皮层回路,LLM 在 prompt 拼装。** 这是机制层面的同构(都不是从固定存储读取),不是修辞层面的类比(不是"agent 像人")。这个区别很重要,它让本篇的论证站得住。

## 2.3 这指向一个未探索的方向

如果人脑的机制是重构式,而且 LLM 本身就是一个生成模型,那也许:

> **agent 的记忆不该是"存原文 + 精确召回",而该是"存碎片 + 图式 + 让 LLM 重构"。**

有一篇 2026 论文已经开始尝试 —— 而且不是普通的"萌芽":**arXiv:2606.06036 · *Memory is Reconstructed, Not Retrieved: Graph Memory for LLM Agents* · Shuo Ji, Yibo Li, Bryan Hooi · ICML 2026 接收**(不是非会议论文)。

### MRAgent 做了什么

它的核心是 **Cue–Tag–Content 关联记忆图 + 主动重构机制**:

```
Cue(细粒度线索)— 通过 Tag(语义桥梁) — 连接到 Content(记忆内容)
```

关键创新:**主动重构(active reconstruction)** —— LLM 推理直接嵌入记忆访问过程,迭代地探索和剪枝检索路径,根据累积的证据动态调整。这和传统的 "retrieve-then-reason"(先检索再推理)的静态管线完全不同。

### 这篇论文最重要的贡献是数学证明,不是实验

附录 C 给了一个**理论分离结果**:

| 命题 | 内容 |
|---|---|
| **C.4 主定理** | 主动检索(active retrieval)**严格强于**被动检索(passive retrieval) |
| **C.6** | 在 Binary-Tree Needle-in-a-Haystack 任务族上,主动检索达到**零误差** |
| **C.7** | 被动检索有 **irreducible error**(不可消解误差),除非预算指数级增长 |

**这是一个数学定理,不是经验观察**。它证明了:对于某类记忆访问任务,Mem0/Zep 那种"先 embedding 召回再让 LLM 推理"的被动范式**理论上做不到零误差**,而 MRAgent 这种"LLM 推理嵌入检索"的主动范式可以。

### 经验证实理论

在 LoCoMo 和 LongMemEval 上(就是 [10](10-memory-frameworks.md) §3 用的同一个 benchmark),MRAgent:
- 比 baseline 高 **23%**
- 同时**降低** token 和 runtime 成本

**这是对 [13](13-reconstructive-memory.md) §2 的强支持**:重构式不只是"更接近人脑"的哲学论点,它在 benchmark 上**精度更高、成本更低**,而且有数学解释为什么(主动 > 被动)。

### 但它仍然没有进生产记忆公司

MRAgent 是 ICML 2026 学术论文,代码开源于 github.com/Ji-shuo/MRAgent。但 **Mem0 / Zep / Letta / OpenViking / MemOS 没有一家采用它的方案** —— 它们仍然是被动检索式。这和 [11](11-causal-state-store.md) 因果状态库的处境一样:**学术有萌芽(而且是 ICML 级的萌芽),工业无人采用**。

但 MRAgent 的存在让 [13](13-reconstructive-memory.md) 的论点从"哲学推测"升级为"有理论 + 有实验 + 有代码的开放方向"。本篇的论证方向被它**验证了**。

## 2.4 重构式记忆 vs 检索式记忆

| 维度 | 检索式(当前所有) | 重构式(本篇提议) |
|---|---|---|
| 存什么 | 完整原文 / 向量 | 碎片 + 图式 + 关系 |
| 召回 | 精确返回原文 | LLM 基于碎片生成叙述 |
| 任务相关性 | ❌ 同查询同结果 | ✅ 同事件不同任务重构不同侧面 |
| token 效率 | 低(返回整段原文) | 高(只存碎片) |
| 幻觉风险 | 低(原文锚定) | **高**(生成 = 幻觉风险) |
| 校准机制 | 不需要(原文就是真相) | **必需**(多 agent 投票 / 一致性检查 / 原文锚点) |

**重构式的两个决定性优点**:任务相关性 + token 效率。这正是 [09](09-stateless-function.md) §5 和 [10](10-memory-frameworks.md) §5 一直头疼的两个问题。

**一个决定性代价**:幻觉风险。这正是 [09](09-stateless-function.md) §2 说的"幻觉 = context 不足以约束输出空间时,模型从训练先验采样" —— 重构本质是生成,生成就有幻觉风险。

## 2.5 校准:重构式记忆能落地的关键

人类记忆之所以能容忍重构,是因为人类有持续的感官校准 —— 照片、他人确认、物理证据。**agent 没有这些。** 所以重构式记忆的真正难题不是"要不要重构",而是"怎么校准重构"。

三种可能的校准机制:

| 机制 | 怎么做 | 代价 |
|---|---|---|
| **原文锚点** | 重构必须能追溯到原始碎片(OpenViking L2) | 锚点本身占存储 |
| **多 agent 投票** | 多个 agent 独立重构,差异大 = 不可靠(grok-build skeptic 思路) | 多倍 LLM 成本 |
| **一致性检查** | 同一事件多次重构,不一致 = 标记 | 重构次数翻倍 |

**这三种校准机制都是反熵措施([04](04-anti-entropy.md) 的验证策略)** —— 重构式记忆引入了新的退化源(重构偏差),需要新的反熵手段。这不是悖论,而是 [04](04-anti-entropy.md) 反退化框架的延伸。

## 2.6 把第一轮的方案升级为重构式

结合 §1(agent 自检索 + 系统提示词目录)和 §2(重构式),第一轮的方案可以升级:

```
旧版(检索式,§1):
  agent 调 trace_decision("D002") → 拿回存储的原文
  
重构式升级:
  agent 调 reconstruct_decision("D002", task="debug race condition")
  → 工具返回碎片: {决策:"mutex", 结果:"死锁", 文件:"...", 时间:"..."}
  → LLM 基于碎片 + 当前任务 context 重构叙述:
     "当时你用 mutex 是因为遇到缓存击穿,但 mutex 在分布式环境下
      会因为持有者崩溃不释放而死锁。当前你的 race condition 场景
      如果也是分布式的,建议直接跳过 mutex 试 channel。"
  → 同时返回原文锚点(用于校准)
```

这更接近人脑 —— 人回忆时不是拿出完整记录,是基于碎片重新叙述。而且它**天然任务感知**(同一事件在不同任务下重构出不同侧面)和 **token 高效**(只存碎片)。代价是需要 §2.5 的校准机制。

# 第三部分:这个范式如何嵌入 insights 系列

## 3.1 重构式 = 生成的记忆 = 连接 12 的生成性

[12](12-generativity.md) 说 "Agent = 反退化(维护) + 生成(创造)"。本篇揭示:**记忆也有生成性的一面**。

当前所有 agent 记忆都是"维护性"的 —— 存原文、召回原文、对抗丢失(反退化)。重构式记忆引入了"生成性记忆" —— 不只是对抗丢失,而是**基于碎片生成新的理解**。这正好接上 [12](12-generativity.md) 的核心命题:

> **agent 的生成性不仅在 LLM 推理([12](12-generativity.md) §2 的 `f`),也在记忆的重构过程。** 记忆不是死的存储,是活的生成。

这是 [12](12-generativity.md) 没覆盖的一个新维度 —— 生成性不只是产出代码/答案,也是产出**对过去的重新理解**。

## 3.2 重构式 vs 因果状态库:正交,可叠加

[11](11-causal-state-store.md) 的因果状态库是关于**存什么**(因果边)。本篇的重构式是关于**怎么召回**(生成 vs 检索)。这是两个正交维度:

```
               检索式        重构式
扁平事实       Mem0          (无人做)
时序事实       Zep           (无人做)
因果边         11(提议)     本篇提议的终极形态
```

**最右下角是 7×24 的可能终局**:因果状态库存碎片(不是原文),LLM 基于碎片 + 当前任务重构因果叙述。这是 [11](11-causal-state-store.md) 因果库 + 本篇重构式的合成。

## 3.3 系统提示词 = 身份层:补 [07](07-philosophy-deep-dive.md) §4

[07](07-philosophy-deep-dive.md) §4 用 Parfit 论证"身份 = 因果链不断",但没说身份层该放在哪。本篇 §1.2 给出答案:**系统提示词** —— 它是唯一每轮恒定注入、不被 compaction 压缩的 context 部分。

这是 07 §4 的工程落点 —— Parfit 的"因果连续性"在 agent 里的物理载体是系统提示词里维护的因果链目录。07 用哲学推出来的结论,本篇给了它一个具体的物理位置。

## 3.4 对 [09](09-stateless-function.md) 的扩展

09 §3 说"所有记忆都是检索 + 注入"。本篇修正:**记忆可以是检索式,也可以是重构式**。重构式仍然是"注入"(把碎片塞进 context),但注入后的 LLM 推理是在**生成**对过去的理解,不是在"读取"存储的原文。

更精确的说法:**所有记忆都是"注入 + LLM 处理",但 LLM 处理可以是"读取"(检索式)或"生成"(重构式)。** 09 没区分这两种 LLM 处理模式 —— 本篇补上了。

## 3.5 整体定位

```
04 反退化(信息论)        12 生成性
     ↓                       ↓
09 无状态函数              重构式 = 记忆的生成性(本篇)
     ↓                       ↓
10 检索式记忆赛道           本篇:重构式记忆(未探索)
     ↓                       ↓
11 因果状态库(存什么)  ←→  本篇(怎么召回)
     ↓                       ↓
07 身份层(Parfit)          系统提示词 = 身份层物理位置(本篇 §1.2)
```

本篇串起了 09/10/11/12/07 五篇,在它们的交叉点上提出了第四种架构(重构式),并落地了第一轮的第三种架构(agent 自检索)。

## 3.6 开放问题(诚实)

本篇提出了方向,没有解决问题。诚实地列出未解:

1. **重构式记忆的幻觉代价如何量化?** [papers/02](../papers/02-compaction-degradation.md) 测了检索式的退化,重构式的退化率没人测过。
2. **校准机制哪个有效?** §2.5 列了三种,没有对比实验。
3. **系统提示词目录何时膨胀到塞不下?** §1.4 提到这个硬伤,但没给具体的分页/聚类方案。
4. **MRAgent 的具体方案如何评估?** §2.3 已介绍 —— ICML 2026 接收,有严格定理(主动 > 被动)和 +23% 实验。但需要单独评估它的 Cue-Tag-Content 图和 [11](11-causal-state-store.md) 因果图如何融合。
5. **重构式和 [11](11-causal-state-store.md) 因果库叠加时的具体接口?** §3.2 说是正交可叠加,但没设计接口。

这五个都是下一篇(或下一次实验)的天然选题。

## 3.7 最终的一句话

> **当前所有 agent 记忆都是检索式 —— 存原文,召回原文。但人脑的记忆是重构式 —— 存碎片,回忆时生成。这个区别被认知科学证明了(Bartlett 1932 / Schacter 2012 / Nature 2023),也有一篇 2026 论文开始尝试(arXiv:2606.06036),但生产记忆公司(Mem0/Zep/Letta/OpenViking/MemOS)没有采用。**
>
> 重构式记忆有两个决定性优点:**天然任务感知**(同一事件在不同任务下重构出不同侧面,正是 [09](09-stateless-function.md) §5 和 [10](10-memory-frameworks.md) §5 一直想要的)和 **token 高效**(只存碎片)。一个决定性代价:**幻觉风险**(生成 = 不确定)。
>
> 本篇还落地了第一轮对话的洞察:**系统提示词作为身份层目录**([07](07-philosophy-deep-dive.md) §4 Parfit 的工程位置),加上 agent 自检索工具,免费解决了任务感知难题 —— 但仍然是检索式,解不了元遗忘之外的问题。
>
> 7×24 AGI 的记忆终局可能是**四层叠加**:系统提示词放 L0 目录(永远知道自己有什么)+ 因果库存 L2 碎片([11](11-causal-state-store.md))+ agent 用工具按任务重构(本篇)+ 多 agent 校准对抗幻觉([04](04-anti-entropy.md) 验证策略的延伸)。**这四层没有任何一家公司全做对了。**
